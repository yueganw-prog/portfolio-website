三、上下文注入策略

每次API调用时，需要注入完整的上下文信息，确保AI输出连贯且符合设定。

3.1 上下文窗口管理

策略：滑动窗口 + 摘要压缩。保留最近10轮对话完整内容，更早的对话压缩为摘要。

示例："玩家在大婚夜展现了诗才，皇帝表示赞赏但有所保留。"

3.2 状态注入

// 状态如何影响AI输出 { "favor": "70", // 高好感 → AI更友善 "wisdom": "65", // 高智慧 → 解锁隐藏选项 "cunning": "45", // 心机值 → 影响对话策略 "flags": ["met_huafei", "tea_crisis"] } // Prompt中的条件指令 "如果favor > 60，皇帝的态度更温和； 如果cunning > 50，皇帝会更警惕； 如果flags包含'tea_crisis'，皇帝会询问此事。"

四、分支叙事引擎设计

玩家选择不仅推动剧情，还通过状态系统影响后续可用选项和剧情走向。

4.1 状态驱动的分支

状态阈值解锁内容设计意图
心机 ≥ 40解锁隐藏选项（暗藏锋芒）鼓励玩家尝试不同策略

4.2 Flag系统

五、调优迭代记录

5.1 问题：角色人设崩塌

现象：皇帝突然说出不符合人设的话。

解决：每次调用重复注入角色卡核心信息 + 限制输出长度。

5.2 问题：选项重复

现象：AI生成的三个选项区别不大。

解决：在prompt中要求"三个选项必须代表不同的策略取向（顺从/主动/试探）"。

5.3 问题：格式不稳定

现象：AI有时输出纯文本而非JSON。

解决：添加"你只能输出JSON"约束 + 正反示例 + 重试机制。

迭代效果：格式成功率从60%提升至95%+，角色一致性从70%提升至90%+
